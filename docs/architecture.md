# SLOPOS-I architecture: what exists today

This page describes the code as it is, not the target. For the target, see the [contract](CONTRACT.md). When the two disagree, this page describes reality and the contract describes where it should go. Last reviewed: 2026-10-30.

SLOPOS-I is an **alpha** X11 desktop environment. Openbox manages windows. SLOPOS adds a session supervisor, a top bar, a desktop window, a Dock, and native applications on its own toolkit: Calculator, Files, Image Viewer, Media, Control Panels and Software. Every surface a SLOPOS session starts is on the SLOPOS toolkit; no GTK program is started by the session. Bundled SLOPOS paths open only the native apps; GTK donor apps that duplicate them are not installed or launched.

## Processes in a session

```
display manager ─► start-slopos-i ─► slopos-session (supervisor, pid lock)
                                        ├─ slopos-control-panels --restore   once, ≤5 s: kept display layout, keyboard and mouse
                                        ├─ openbox            Required: its failure ends the session
                                        ├─ picom / xcompmgr   Optional: skipped if missing or SLOPOS_NO_COMPOSITOR
                                        ├─ slopos-desktop     Optional: desktop icons; off with SLOPOS_NO_DESKTOP
                                        ├─ slopos-topbar      Important: restarted with backoff, session survives
                                        └─ slopos-dock        Important: as above; off with SLOPOS_NO_DOCK
apps launched from the top bar, desktop or Dock: detached (setsid), reaped, not supervised
```

- `start-slopos-i` is the X session entry point (`packaging/slopos-i.desktop` runs it). It sets up D-Bus activation and the source-tree or installed share directory, then executes `slopos-session`.
- `slopos-session` (`crates/slopos-session`):
  - takes a lock at `$XDG_RUNTIME_DIR/slopos-session<display>.pid`, so a second instance refuses to start;
  - runs `slopos-control-panels --restore` (killed after 5 s) so the display layout and keyboard/mouse settings kept in Control Panels apply before anything sizes itself to the screen;
  - configures the environment (`environment.rs`): `XDG_*`, the GTK theme and GTK 2 rc for the chosen appearance and the Openbox config path, then paints the desktop itself: the saved picture (`slopos_core::wallpaper`), Platinum's default blue field, or the appearance colour, through `slopos_ui::platform::x11::set_root_background` (a retained root pixmap announced in `_XROOTPMAP_ID`). `slopos-session --paint-desktop` repaints after a change; no feh, xsetroot or PCManFM is involved;
  - supervises its children (`supervisor.rs`). After a crash a child is restarted with a delay of 250 ms × 2ⁿ. After 5 fast failures in a row it is given up, and that is reported once.
  - `slopos-session --logout` sends SIGTERM to the running supervisor, which stops the children in reverse order (SIGTERM, then SIGKILL after 2 s). The Openbox root menu and the top bar's System menu both use it.
- Appearances: `platinum` (default), `classic`, `graphite` and `oled`. Each one picks an Openbox rc file, a GTK theme and a root colour. A user's own `~/.config/slopos-i/openbox/rc.xml` always wins.

## The SLOPOS toolkit (`crates/slopos-ui`)

| Module | Contents |
|---|---|
| `foundation`, `layout` | Integer geometry (`Rect`, `Scale`), colours, insets and layout helpers. |
| `render` | `RasterSurface`: a tiny-skia pixmap at an integer scale, with rect fill/stroke, image and text drawing, a nested clip stack (`push_clip`/`pop_clip`/`with_clip`) and PNG output. All coordinates are logical pixels. **Recording mode** (`RasterSurface::recording`, `take_recording`, `render/recording.rs`): the same drawing calls are captured as a `render::list::DrawList` instead of being rasterised, so unchanged app `paint` code can feed the GPU path. Each call validates its geometry as the reference does and returns the same error. `stroke_rect` records its four edge fills in the reference order, so translucent corners blend twice as they do directly; `clear` records a full-surface fill, which equals the reference only on a blank surface or for an opaque colour (any other use is a recorded failure); `draw_surface`, unbalanced clips and a full command limit are failures that `take_recording` reports. The bridge is this mode of `RasterSurface`, not a separate trait, because `App::paint`, the controls and the primitives all take `&RasterSurface`. It covers every call that paints through the surface's methods. It does not cover code that reads or writes device pixels directly (`data`, `pixel`, PNG encoding), `draw_surface`, the older `scene`/`scene_raster` recorder, or popup surfaces, which stay on the CPU. **Parity tests:** the Calculator-shaped sequence (`calculator_like`, rebuilt from the public controls because the app crate is not reachable from here), translucent colours, nested clips, text, images with opacity, and bicubic images must replay to byte-identical pixels at scales 1 and 2; with `gpu` the same frame also goes through `WgpuExecutor`. |
| `scene`, `scene_raster` | Early renderer-neutral, bounded command recording (clear, fill/stroke rectangles) and a software adapter that replays into the existing `RasterSurface`. No GPU renderer or full UI scene graph yet. |
| `render::list` | Backend-neutral `DrawList`: a bounded recording of logical-pixel commands (filled, rounded and stroked rectangles, text runs, image blits with opacity, nested clips). Images are owned by the list and referenced by handle. Clip balance, image handles and command limits are checked when a command is recorded. `execute` replays onto `RasterSurface`, the CPU reference. Semantics: half-open, non-anti-aliased rectangles; source-over with colour alpha; clips intersect; execution stops at the first failing command; each stroke or corner pixel is painted once. **Parity suite** (in the module's tests): golden FNV checksums of the device bytes for fill, rounded, stroke, image and clip lists at scales 1 and 2; hand-derived corner and clip pixels; source-over alpha; zero-size and negative-size input; overflow; clip restoration after errors; and an exact 2x upscale from scale 1 to scale 2 for rectangles, outlines, clips and images. Text runs are checked against direct `draw_text` output, not a checksum, because glyphs come from the installed fonts. Rounded corners are a fixed integer pixel-centre test, capped at 256 logical pixels. |
| `render::gpu` | Optional wgpu executor behind the `gpu` cargo feature (off by default; the default build does not compile or link wgpu). `WgpuExecutor` implements the `render::list::DrawExecutor` trait, which `CpuExecutor` (`RasterSurface`) also implements as the reference. It requests a headless adapter with no window or display handle and draws into offscreen premultiplied RGBA8 frames. Recording (pure CPU, no device) turns the list into device quads with scissor rects from the clip stack. Fills, rounded rectangles and outlines use the reference geometry; text runs are rasterised on the CPU and drawn as images; integer-scale images sample nearest and other scales sample bicubic. Blending is premultiplied source-over. **Parity:** the test renders the phase-A suite plus phase-B bicubic images through both paths and pins every differing byte. On llvmpipe (software Vulkan) only the bicubic image path differs, by ±1 in one channel at 44 bytes; everything else is byte-exact. When no adapter exists the test prints `NOT_RUN` and returns; set `SLOPOS_REQUIRE_WGPU_ADAPTER=1` to fail instead. **X11 presentation (phase C, readback):** `platform::x11::present_gpu_list` draws a `DrawList` with this executor, copies the frame back with `read_pixels` and sends it through the same damage-driven PutImage path as the CPU surface. The test `gpu_readback_presented_to_the_display_matches_the_cpu_reference` checks the window pixels against the CPU reference on a live X server. Not yet: a direct GPU present (DRI3 or the Present extension) and texture caching. The GPU frame starts from the window's persistent surface, and a successful GPU paint hands its result back to that surface, so repeated paints that do not clear match the CPU path (test `repeated_translucent_gpu_frames_build_on_the_surface_as_the_cpu_does`). A frame the list cannot express (a translucent or clipped `clear`, `draw_surface`, an open clip at the end) is painted on the CPU for that frame only; the GPU stays on. A layer larger than the device texture limit is refused before drawing. Phase D: with `SLOPOS_GPU=1` the main window of every app paints through this path (recording, then replay); the default stays CPU, and the GPU path stays opt-in until the owner has verified it on real hardware. On llvmpipe the window path matches the CPU frame byte for byte (test `a_recorded_window_frame_presented_on_the_gpu_matches_the_cpu_paint`). Differences and licences are recorded in the module docs and `THIRD_PARTY_LICENSES.txt`. |
| `animation` | Pure, deterministic timeline sampling (linear/cubic easings and reduced-motion completion). The caller remains responsible for event-based frame scheduling. |
| `text` | `Font`, `measure`, and `caret_stops`/`hit_test` for caret placement (char boundaries, clusters and RTL runs). cosmic-text shaping, preferring Liberation Sans or DejaVu Sans. |
| `theme` | Semantic colour roles (`Palette`: surface, content, ink, selection, focus, menu highlight, danger, scrollbar…). Only the provisional Platinum values exist. |
| `accessibility` | `window_tree`: builds an app's flat AccessKit window tree with focus fallback. `text_label`: a `Label` node with its text as the value, which is where AccessKit takes a label's AT-SPI name and text from. `TreeScaler`: the host puts the UI scale on the root's transform (remembering the root across updates), so AT-SPI extents are in window pixels at 2x. |
| `image` | `Image`: PNG decoding and SVG rasterisation (resvg, with system fonts for SVG text), bilinear scaling, and `compose_background` (fill, tile or centre over a backdrop) for desktop pictures. |
| `icons` | `IconLookup`: freedesktop icon-theme lookup with `Inherits`, size matching, `hicolor` and `/usr/share/pixmaps`. Default theme `SLOPOS-Platinum`, overridden by `SLOPOS_ICON_THEME`. |
| `primitives` | Classic component painters, e.g. the button plate (Regular, Default and Secondary × Rest, Pressed and Disabled, at any size). |
| `controls` | Interactive controls as explicit state machines, each with keyboard, pointer and AccessKit support: `Button` (text, or an icon with the label kept as the accessible name); `TextField` (single-line Unicode editing, word motion, shift/drag selection, Ctrl+A/C/X/V/Z, placeholder, max length, steady caret, `TextInput` with SetValue); `TabStrip` (equal-width tabs; pointer, Left/Right/Home/End; `TabList` and `Tab` nodes); `FocusChain` (Tab/Shift+Tab); `ScrollState` (offset, wheel-over-area, track paging, thumb drag, Classic scrollbar); `ListView` (virtualized rows, single/multiple selection with Shift/Ctrl click and keys, type-ahead, double-click/Enter activation, context-menu requests, bounded `ListBox` a11y); `Menu` and `MenuBar` (in-window pull-down/context menus, keyboard and pointer, shortcuts text, separators, disabled/checked/checkable items, F10; a global mode in which the bar takes no space and choices arrive from the shell); `Dialog` (application-modal alert or text prompt with scrim, Enter/Escape; a standalone mode for popup windows); `TextField` secret mode (bullets, no copy/cut, `PasswordInput` with no value in the accessibility tree); `PopUpButton` (pop-up menu control: opens over the current value, press-drag-release or click, `ComboBox` semantics); `FileChooser` (modal dialog in three modes: Open, with optional multiple selection and named filters with a Filter button; Select Folder; and Save with a file-name field, validated names and an overwrite question that defaults to Cancel; sorted, capped folder list, path field, Up); `OpenWithChooser` (application list for a file, default marked, Cancel/Open); `Slider` (horizontal, or vertical with `Slider::vertical`: a fader with its maximum at the top), `Checkbox`, `ProgressBar` (determinate or static indeterminate). |
| `platform` | `App` trait, `Control` and `WindowOptions`. The x11rb host: a poll(2) loop that sleeps until there is input, a timer or a `Proxy::wake()` from another thread; frames sent with PutImage, damage-driven: each window keeps a copy of the pixels the server holds (`platform/present.rs`, no X11 types), sends only the bounding rectangle of the pixels that changed, sends nothing for an unchanged frame, and resends the whole frame after Expose, a resize or a remap (strips split by the server's request limit; no MIT-SHM, so the upload is copied through the connection); the damage is one rectangle per frame, found by comparing with the copy, and the GPU readback path is `x11::present_gpu_list` under the `gpu` feature; with `SLOPOS_GPU=1` the main window's `App::paint` runs into a recording surface and the replayed list is presented through it, falling back to the CPU when no adapter exists or a GPU frame fails (the reason is logged once; the window then stays on the CPU) (`platform/paint_path.rs` holds the choice, with no X11 types; popups stay on the CPU; DRI3 or Present, a direct GPU present, is not done); Normal, Dock (with struts, which `Control::set_strut` can change at run time) and Desktop window kinds; a pointer leave that the server reports while the window itself moves or grows under a still pointer is not delivered while the pointer is still over the window or the frame the window manager put around it (a window covering it is a real leave); override-redirect popup windows with pointer/keyboard grabs (`Control::open_popup`, `App::paint_popup`); desktop-wide key grabs (`WindowOptions::global_keys`, all lock-modifier combinations); HiDPI via `SLOPOS_SCALE`/`GDK_SCALE`; the X11 `CLIPBOARD` selection (`Control::set_clipboard`, `request_paste`; UTF8_STRING/STRING/TARGETS, 256 KiB, no INCR); keymap refresh on `MappingNotify`; AccessKit trees on AT-SPI (feature `atspi`, on by default); `set_root_background` for the desktop picture. `global_menu` (feature `global-menu`, on by default) exports an app's `App::menu_bar` over `org.gtk.Menus`/`org.gtk.Actions` on the session bus and tags the window with `_GTK_UNIQUE_BUS_NAME`, `_GTK_MENUBAR_OBJECT_PATH` and `_GTK_APPLICATION_OBJECT_PATH` before it maps; enabled/checked changes are pushed with `Changed` signals. The app hides its in-window bar only while the top bar owns `org.slopos.GlobalMenu`; a blocking NameOwnerChanged watcher brings the bar back if the top bar exits. `menu_import` is the other side: it reads any window's `org.gtk.Menus`/`org.gtk.Actions` model (sections, submenus, accelerators, check/radio state) and activates actions. |

An app implements `App::event`, `App::paint` and, optionally, `App::accessibility`, then calls `platform::run`. The Calculator (`apps/calculator/src/main.rs`) is the reference example.

Not built yet: drag and drop, IME pre-edit (XIM/IBus), trees/icon grids, `slopos-appkit`, Vello rendering and direct GPU presentation (the opt-in wgpu executor is described above), an advanced composited scene graph, and theme datasets beyond the provisional Platinum colours. See [the UI toolkit program](ui-toolkit-program.md) for in-repository toolkit milestones and optional external distribution; [native application plan](application-platform.md) and [swarm execution](swarm-execution.md) document future product slices, not implemented features.

## The Dock (`crates/slopos-dock`)

- **Window:** a bottom-centred window of type `_NET_WM_WINDOW_TYPE_DOCK` that reserves its strip with `_NET_WM_STRUT_PARTIAL`. It resizes and re-centres as tiles come and go. Its strut is published from the window manager's ConfigureNotify, as the root-relative span the window actually has.
- **Pins:** read from `~/.config/slopos-i/dock-pins`, one desktop id per line. Without that file it pins one installed app per role: Files, browser, terminal, editor, Calculator, Media, Software and Control Panels. The SLOPOS roles name only the native apps; a donor file manager never stands in for Files. `slopos-dock --pin-defaults` writes the defaults to the file.
- **Running windows:** `windows.rs` has its own X connection on a thread. It watches `_NET_CLIENT_LIST_STACKING`, `_NET_ACTIVE_WINDOW` and each client's title and state. Windows are matched to apps by `WM_CLASS`/`StartupWMClass` (`model.rs`, tested without X). Unpinned running apps appear after a separator.
- **Interaction:**
  - Click launches the app, raises its top window, or cycles through its windows when the app is already in front.
  - Middle-click starts another instance.
  - One dot per window, up to 3. The dots are amber when a window asks for attention.
  - Screen readers see a toolbar of buttons.
- **Auto-hide** (off by default): turned on or off from the Dock's right-click menu ("Automatically Hide and Show the Dock") or with `slopos-dock --autohide on|off`, saved in `~/.config/slopos-i/dock.conf` (or `$XDG_CONFIG_HOME/slopos-i/dock.conf` when that is absolute). A running Dock applies the setting from its menu at once; the command line saves it and the Dock applies it when it next starts. Hidden, the Dock leaves a 4-pixel strip on the bottom edge and reserves no space, so maximised windows use the whole screen. The pointer reaching the strip shows it again; it hides 600 ms after the pointer leaves, and not while its menu is open. The state machine is `autohide.rs` (tested without X); the window's strut changes at run time through `Control::set_strut`. `scripts/qa/dock-autohide.sh` checks it under Xvfb.
- **Not built yet:** drag-to-reorder, pin/unpin from the UI, other context-menu actions, multi-monitor placement and a Settings panel.

## The top bar (`crates/slopos-topbar`)

- A 26-pixel `_NET_WM_WINDOW_TYPE_DOCK` window across the top with a strut. One instance per display ("Refusing to start a second SLOPOS top bar").
- **Menus:** the System menu (About, Control Panels, Software, Volume Mixer, Desktop Picture, appearance choices, Switch User, and Log Out/Restart/Shut Down with confirmation) and either the desktop menus (File, View, Special, Help) or the focused window's menus. The top bar owns `org.slopos.GlobalMenu` and imports the focused window's `org.gtk.Menus` model through `slopos_ui::platform::menu_import`, so SLOPOS toolkit apps and GTK applications alike show their menus here; choosing an item activates the app's action. Windows without exported menus get Close, Minimise and Zoom (EWMH requests). Menus are toolkit popup windows with keyboard navigation.
- **Status items** come from `slopos-services` on a blocking thread: sound (output volume, mute), network (connection name, "Offline", "Network unavailable"), battery when there is one, and the clock (a timer only for the minute change).
- **Volume Mixer:** a left-click on the sound item opens the mixer as a popover under it; another click on the item, Escape or a press outside closes it. A right-click opens the sound menu, whose "Volume Mixer…" entry does the same. The popover shows the same `MixerView` as the app and sends its changes to the top bar's status provider. With no sound server it says "Sound unavailable: …"; opening the popover asks the status thread to connect again, so a server that started later is found without a restart. `scripts/qa/topbar-mixer.sh` checks the popover and that reconnect under Xvfb. The standalone app retries the same way on R.
- **Launcher:** fuzzy search over `.desktop` entries in a popup, opened by Super+Space (Openbox sends SIGUSR1), Ctrl+F2 (a global key grab) or the System menu.
- **Notifications:** an `org.freedesktop.Notifications` 1.2 server (body, actions, persistence; expiry, replace, close, `ActionInvoked`/`NotificationClosed`), shown as toasts under the bar's right end, three at a time.
- **Not built yet:** status popovers for Wi-Fi, Bluetooth, battery and clock (the sound popover is the Volume Mixer), volume and brightness OSDs, a notification history, multi-monitor bars.

The KDE/Canonical AppMenu protocol is wired in the bar. `registrar_bus.rs` owns `com.canonical.AppMenu.Registrar` on the session bus (zbus): `RegisterWindow(u, o)` and `UnregisterWindow(u)` from the caller's own connection, `GetMenuForWindow(u)`, and the `WindowRegistered(u, s, o)` and `WindowUnregistered(u)` signals. The pure `menu_registrar.rs` state machine decides every change: one service per window, owners may only unregister their own windows, and a window leaves when X reports `DestroyNotify` (the registrar selects `StructureNotify` on each window it registers) or when its bus name vanishes (`NameOwnerChanged`). If the name is taken (another registrar) or there is no display, the bar still reads window properties. `windows.rs` reads `_KDE_NET_WM_APPMENU_SERVICE_NAME` and `_KDE_NET_WM_APPMENU_OBJECT_PATH`; both must be valid. A focused window's menu address is its own property, otherwise its registration. `dbusmenu.rs` is the `com.canonical.dbusmenu` client: `GetLayout(0, -1)` decodes the wire tree into `RawNode`s and `menu_registrar_layout` parses it. Top-level submenus become titles; a submenu inside a menu shows as a disabled header followed by its entries; hidden items are dropped. `AboutToShow` runs when a title opens, `LayoutUpdated` and `ItemsPropertiesUpdated` refetch the tree, and choosing an item sends `Event(id, "clicked")`. Menu precedence: GTK `org.gtk.Menus` first, then dbusmenu, then the Close/Minimise/Zoom fallback. Verified without a display: the decoder, bar model and property parser unit tests, and `registrar_and_client_show_a_registered_application_menu`, which runs a private `dbus-daemon` with a fake application (registration, the signal, layout, about-to-show, click, and cleanup when the application leaves). NOT_RUN: a live Qt or GTK application under the X session, and the X `DestroyNotify` path. `settings.ini` sets `gtk-shell-shows-menubar = 1`, so GTK 3 applications with a menu model hide their in-window menubar and rely on the shell to show it; this is read from the config, not checked live.

## The desktop (`crates/slopos-desktop`)

- A `_NET_WM_WINDOW_TYPE_DESKTOP` window the size of the screen, under every window. It shows a copy of the root picture the session paints (re-read when `_XROOTPMAP_ID` changes), so the desktop looks the same with or without it, and follows screen-size changes.
- **Icons:** Home, removable volumes mounted under `/media` and `/run/media`, the items of `XDG_DESKTOP_DIR` (hidden files skipped, at most 400) and the Trash (full or empty), placed from the top-right corner down. Positions the user drags to are kept per item in `~/.config/slopos-i/desktop-positions`.
- **Interaction:** click/Ctrl-click selection, drag to a free cell, double-click/Return/Ctrl+O to open (Files for folders, volumes and Home, `slopos-files --trash` for the Trash, the default application for files), arrows, type-to-select, Ctrl+Shift+N for a new folder that never replaces one, and a context menu (New Folder, Change Desktop Picture…, Open Desktop in Files). Items are a `List` of `ListItem`s for assistive technology.
- Refresh is event driven: inotify on the desktop folder and the Trash, `POLLPRI` on `/proc/self/mountinfo` for mounts, X events for the picture and size.
- **Not built yet:** rename, Move to Trash and drag and drop between the desktop and Files, mounting unmounted volumes, one window per monitor.

## Packages and CI

- **Packages:** `install.sh` installs from source into a prefix: the session, top bar, desktop, Dock and the native apps (Calculator, Files, Image Viewer, Media, Control Panels, Software), their desktop entries, Openbox and GTK themes, the icon theme and wallpapers. The runtime dependency lists (`packaging/deps`, the Arch ISO list and the VM installer) no longer include the GTK donor apps that duplicate SLOPOS's own (PCManFM, Ristretto, galculator, mpv, pavucontrol, blueman, arandr, lxappearance, xfce4-settings, the NetworkManager applet); they keep the services the native apps use (NetworkManager, PipeWire, BlueZ, UPower, xfce4-power-manager). `assets/config/mimeapps.list` names only native apps for images, media and folders.
- **Live ISO:** `packaging/iso/build-live-iso.sh --arch amd64|arm64` builds an Ubuntu 24.04 casper live image (BIOS+UEFI for amd64, UEFI for arm64) that autologins into SLOPOS-I; `test-live-iso.sh` boots it in QEMU and checks the desktop and launcher. `.github/workflows/live-iso.yml` builds both and boot-tests amd64.
- **CI:** `.github/workflows/ci.yml` is one job that runs fmt, clippy `-D warnings`, the workspace tests, the Python architecture/spec checks, shell syntax checks, and `scripts/smoke-session.sh`. The smoke test boots a real session under Xvfb and checks the top bar, the desktop window, the Dock and Calculator, then logs out and checks that every process exited.
- **Nightlies:** `nightly.yml` publishes the `.deb` and `.pkg.tar.zst` from `main` to the rolling `nightly` release.
- **Scheduled:** the heavy X11 QA runs nightly (`qa.yml`). The ISO, installed-VM, recovery and hardware-contract workflows run weekly.

See [development.md](development.md) for commands.

## Installer

The live ISO includes Calamares 3.3 (`calamares`, Ubuntu noble universe) as its graphical disk installer. `packaging/iso/installer/` holds `settings.conf`, the per-module YAML in `modules/`, the `slopos` branding (`branding/slopos/`) and the "Install SLOPOS-I" launcher; `live-installer.sh` copies them into the live root, and `scripts/check-live-installer-config.sh` checks them in `live-iso.yml` before the ISO build. The launcher runs `pkexec /usr/bin/calamares`; a polkit rule (`49-slopos-live-installer.rules`) lets only the live user run it, in the active local session, without a password. The sequence is welcome, locale, keyboard, partition, users and summary, then the install steps: partition (erase disk is selected by default, and manual partitioning is hidden), mount, unpackfs (copies `casper/filesystem.squashfs` from the medium, which keeps `/boot` so the installed system has a kernel), machineid, fstab, locale, keyboard, users, displaymanager (LightDM; automatic login only when the users page ticks it, otherwise password login), networkcfg, hwclock, shellprocess (`strip-live-system.sh` purges casper and removes the boot-to-casper config, the launchers and the polkit rule from the installed system before the initramfs job), initramfs, bootloader (GRUB for UEFI and, on amd64, BIOS), umount, then finished. The installer does not sign anything for Secure Boot, so an installed system will not boot with Secure Boot enforced. It does not install over the network, and it does not offer partition layouts other than erase. Replace and Alongside can still appear on a disk that has room for them. Nothing here has been run on a disk yet; the install is NOT_RUN.

## Native System Monitor (`apps/system-monitor`)

- **Model** (`model.rs`, `procfs.rs`, `format.rs`, `policy.rs`): pure parsers over the text of `/proc/stat`, `/proc/meminfo`, `/proc/diskstats`, `/proc/<pid>/{stat,status,cmdline}` and `/etc/passwd`, and a `Monitor` that turns two snapshots into CPU, disk-rate and process-share values. A value that needs two readings, or whose file could not be read, is shown as "measuring" or "unavailable", never as zero.
- **Source** (`source.rs`): the only code that touches the system (the `Source` trait; `LinuxSource` reads `/proc`, calls `statvfs`, `geteuid` and `kill`). Tests use fixture text and a fake source.
- **Window** (`app.rs`): tabs from `controls::tabs::TabStrip`, the process list from `ListView`, a filter `TextField`, Inspect and End process buttons, and a `Dialog` for the confirmation (default button No).
- **Sampling exception to the no-polling rule.** A task manager has to sample over time, so the window keeps one one-second timer while it is visible. `Event::Visibility(false)` (the window is unmapped: hidden, minimised or on another workspace) stops it: the pending tick samples nothing and does not re-arm. Nothing else polls. Reads are blocking calls on the event thread, one pass a second. This is the only timer exception in the app set; other apps stay event driven.
- **End process.** The request is checked when the confirmation opens (PID 1 and other users' processes are refused without a dialog) and again after Yes, against the PID's current start time, owner and state (a reused PID or an exited process is not signalled). SIGTERM is sent with `kill(2)`, one line is written to standard error for each attempt, and a one-second read-back reports ended or still running. Force kill (SIGKILL) and priority changes are not offered.
- **GPU.** Built only with `--features gpu` (which enables `slopos-ui/gpu`); the adapter is probed once, when the GPU tab is first shown. Otherwise the view says the build has no GPU support.

## Known gaps

The [ledger](contract/ledger.md) has the dated evidence; its section G.2 is the prioritized register of remaining work (GAP-* IDs). In short:

- Native Files has no drag and drop, icon view, thumbnails, properties window, removable-volume mount/eject or network mounts yet, and has not passed installed-package VM acceptance. Text editor is not native yet (Mousepad is still used). System Monitor is native (`apps/system-monitor`) but has no network view, force kill or priority changes. The native terminal (`apps/terminal`, PTY, VT parser, grid, CPU drawing) is preferred when installed; the GPU terminal path is not built, and a shell-only check of its escape handling has not been run on a live X server.
- File dialogs: the chooser backend is routed by the packaged `slopos-portals.conf`, but no live xdg-desktop-portal frontend has run it, so GTK and Qt apps are not confirmed to use it. The D-Bus activation file ships (`org.freedesktop.impl.portal.desktop.slopos.service`), but no live frontend has started it. Open With offers only the native SLOPOS applications (`slopos_core::mime::NATIVE_APP_IDS`) and does not persist a default application (no default-apps writer exists yet). The backend refuses more than 4 concurrent requests and over-long options. The portal's `directory`, `multiple` and filter options are implemented, but real-application runs are NOT_RUN.
- No OSDs, and no status popovers besides the Volume Mixer; workspaces UI, lock screen, polkit agent, network-secret agent (Wi-Fi passwords are asked by Control Panels only) or BlueZ pairing agent (devices that need a PIN or passkey confirmation fail with BlueZ's error).
- No production software catalogue or publisher key exists yet, so Software shows "No software catalogue is installed" on a fresh system.
- The legacy GTK crates (`slopos-shell`, `slopos-settings`, `slopos-catalogue`) are still built in the workspace but no longer shipped or started.
- X11 only. GNOME and KDE are leaving X11, so distribution support for X11 logins has to be checked per release (§21.10).
- Not tested on real hardware or on the Raspberry Pi edge target.

## Native Image Viewer (`apps/image-viewer`)

- **Decoding** (`decode.rs`, adapted from the archived Preview decoder): PNG, JPEG, GIF, BMP, WebP and TIFF through the `image` crate with only those codecs enabled, SVG through resvg. The format is sniffed from content. Files must be regular and at most 64 MB; dimensions are checked before decoding (40 MP, 32 768 px per side) and the decoder's allocation limit stops decompression bombs. EXIF orientation is applied. Decoded images live in a 256 MB LRU cache.
- **UI** (`main.rs`): menu bar (File, View, Go), toolbar, Open dialog filtered to images, next/previous/first/last through the image's folder with the next image decoded ahead, Fit/1:1/zoom (keys, buttons, wheel), drag to pan, double-click to toggle Fit and 1:1, status line with size, format, zoom and position. Decoding runs on a worker thread and wakes the window.
- Not built: rotation and editing, slideshow, thumbnails grid, colour management (ICC profiles are ignored), animated GIF/WebP playback (first frame only), HEIF/AVIF/RAW.

## Native Files (`apps/files`)

- **Model** (`model.rs`, from PR #35): non-recursive listing via `symlink_metadata`, so directory symlinks are never traversed while listing; folders over 8192 entries fail explicitly instead of truncating; Back/Forward history.
- **Workers** (`worker.rs`): one folder-reading thread (bounded queue, stale results dropped), one thread per file operation with cancel and throttled progress wakes, and an inotify watcher thread. All wake the UI through `Proxy`; nothing polls.
- **Archives** (`archive.rs`): Compress (zip, tar.gz) and Extract Here (zip, tar, tar.gz, tar.xz, tar.zst) run as operations with progress and Cancel and the same partial-then-no-replace commit. Extraction refuses absolute and `..` paths, creates symlinks only after all files and only if they stay inside, skips hard links and devices, drops setuid/setgid/sticky, and caps entries (200,000) and bytes (200× the archive, ≥256 MiB, ≤64 GiB, never past free space − 64 MiB). A single top-level folder is not nested again. Pure-Rust crates: `tar` (MIT/Apache-2.0), `zip` with deflate only (MIT; `zopfli` Apache-2.0), `lzma-rs` (MIT), `ruzstd` (MIT), `flate2`.
- **Operations** (`ops.rs`, `trash.rs`): copies are written under a private partial name and committed with `renameat2(RENAME_NOREPLACE)`; cancel or failure removes only the partial; Replace swaps the old item aside and deletes it only after the new one is in place; cross-device moves delete the source only after a committed copy; symlinks are copied as links; FIFOs and devices are refused; copying a folder into itself is refused. Trash follows the freedesktop spec (home trash, or `$topdir/.Trash-$uid` on other volumes), and restore never overwrites.
- **UI** (`main.rs`): menu bar (File, Edit, View, Go; global when the shell runs), icon toolbar (Back, Forward, Enclosing Folder, Home), location field (Ctrl+L), a Places sidebar (Home, the standard folders that exist, Computer, Trash) that follows navigation, theme icons per row (special folders, MIME type, generic fallback), the shared `controls::list::ListView` with Name/Size/Modified/Kind columns, context menus, Rename/conflict/confirm dialogs, Trash view (restore, delete, empty), hidden-file toggle, status bar with progress and Cancel. Opening uses `slopos_core::mime` (the default app from `mimeapps.list` or a desktop entry's `MimeType`), falling back to `xdg-open`.

## Native Media (`apps/media`)

- **Engine** (`engine.rs`): GStreamer `playbin` with a bin of `videoconvert ! videoscale ! capsfilter(RGBA) ! appsink` (one frame buffered, newest wins; frames over 1920×1080 are scaled down by GStreamer). A bus thread turns messages into events and wakes the window; there is no polling. Paused preroll frames arrive through `new_preroll`. Without a sound server or ALSA device, audio goes to a synchronised `fakesink` instead of failing. Sidecar `.srt/.vtt/.ass/.ssa` files with the same stem are loaded as subtitles (GStreamer cannot detect very short subtitle files).
- **Errors**: unknown formats say so; a missing decoder names the codec and the package that usually provides it (`gstreamer1.0-libav` for H.264/H.265/AAC, which SLOPOS does not ship).
- **UI** (`main.rs`): video area scaled to fit, seek slider with times, Play/Pause, volume slider, Mute, Subtitles toggle, Open dialog filtered to media; Space/K, Left/Right (±5 s), Up/Down (volume), M, Ctrl+O. A 250 ms timer runs only while playing.
- Licences: GStreamer core and base/good/x plugins are LGPL-2.1+, linked dynamically; gstreamer-rs is MIT/Apache-2.0.
- Not built: playlists, fullscreen, audio/subtitle track selection, hardware decoding, embedded subtitle tracks UI.

## Native Control Panels (`apps/control-panels`)

- **Providers** (`services.rs`): one current-thread Tokio runtime connects the `slopos-services` clients (NetworkManager, audio, BlueZ, timedated, brightness, RandR displays, XKB/XInput input), forwards their snapshot streams and runs changes; it blocks on streams and the command channel and wakes the window. A missing provider shows "unavailable" with the reason and disables its controls.
- **Panels:**
  - Network: networking and Wi-Fi toggles, scan, network list marking the connected and saved networks; Join (secured networks without a saved profile ask for the password in a dialog with a secret field; the profile is validated, then `AddAndActivateConnection`), Disconnect, Forget.
  - Sound: Output and Input device pop-ups, volume and mute for the chosen devices; an Application section to pick a playing application and set its volume, mute it or move it to another output.
  - Display: backlight; Display, Resolution, Refresh rate, Rotation and Position (right/left/above/below/mirror of the main display) pop-ups, Use this display, Show the menu bar here. Changes go through RandR as one plan (modes and rotations checked, CRTCs shared for mirroring, screen resized under a server grab); every change asks "Keep these display settings?" and reverts after 15 seconds without an answer. Kept layouts are saved to `displays.conf` and re-applied at login when the same monitors are connected.
  - Bluetooth: adapter power, Search for Devices, device list (connected, paired, then by name), Pair (Cancel Pairing while it runs; paired devices are trusted and connected), Connect/Disconnect, Forget.
  - Date & Time (automatic time), Desktop (bundled patterns with thumbnails, Choose Picture…; saved to `~/.config/slopos-i/wallpaper` and repainted at once), Appearance (Platinum, Classic, Graphite, OLED through `slopos-appearance`).
  - Keyboard & Mouse: keyboard layout (from the XKB rules list, applied with `setxkbmap`), repeat delay and rate (XKB controls), pointer speed and natural scrolling (libinput properties, only when a device takes them), left-handed buttons. Saved to `input.conf` and re-applied at login.
- **UI:** sidebar with theme icons, File/View menus (global when the top bar runs), Ctrl+1…8 to switch panels, `--network`/`--sound`/`--desktop`/`--keyboard`… flags to open a panel, `--restore` (also `--apply-displays`, `--apply-input`) for the session; pop-ups with nothing to choose are skipped by Tab; status text is red only for failures.
- Not built: a network-secret agent for other apps, enterprise/hidden Wi-Fi, VPN; a BlueZ pairing agent (PIN/passkey); time zone selection; Dock settings; per-monitor scale.

## Native Software (`apps/software`)

- **Trust and transactions** (`trust.rs`, `install.rs`): the catalogue and every entry are Ed25519-signed and checked against `/etc/slopos-i/software/trust.json` (regular, not group/world-writable files only); installs stream over HTTPS to a partial file, check size, SHA-256 and the ELF header, then commit with rollback; interrupted transactions are recovered at start-up.
- **Window** (`store.rs`, `window.rs`): lists the verified catalogue's apps for this architecture plus installed AppImages, with Install/Update/Remove…/Open, real byte progress and Cancel. A missing or rejected catalogue offers nothing and says why; installed apps can still be removed. Removal asks first; failures show the transaction's own error.
- Not built: a published production catalogue and publisher key (owner step), screenshots and ratings, automatic update checks, distribution packages.
